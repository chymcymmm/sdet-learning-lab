# 2026-09-16｜Java 类与对象 + JUnit5 断言入门

## 1. 学习目标

- 理解 Java 的类、对象、方法、参数、返回值
- 理解 JUnit5 的 `@Test`、`assertEquals`、`assertThrows`
- 建立"测试的本质"这个核心认知

## 2. 核心知识

### Java 基础

- 类 = 图纸，对象 = 按图纸造出来的东西
- `VipUserPointComponent` 是类，`component` 是对象
- `component.addPoint(dto)` = 命令 component 这个对象执行 addPoint
- 方法格式：`返回类型 方法名(参数)`
- `void` = 不返回结果；`Integer` = 返回一个整数
- 参数个数 = 逗号数 + 1

### JUnit5

- `@Test`：标记测试方法，JUnit 负责调用它（相当于"报名参赛"）
- `void`：测试方法无返回值，靠**是否抛异常**判定失败
- 执行链：`mvn test` → Surefire → JUnit → 扫描 `@Test` → 调用
- `assertEquals(期望值, 实际值)`：验证**值**相等
- `assertThrows(异常类, () -> {...})`：验证**抛了异常**

### 测试的本质（最重要）

```
① 调用被测代码 → ② 拿到实际结果 → ③ 和期望比较
```

少了第①步（不调用被测代码，自己给变量赋值再断言），测试就是假的。

## 3. 今日收获

- 以前以为"会报错"就是失败，现在知道是"抛异常 → JUnit 捕获 → 判定失败"
- 明白了 `assertEquals` 和 `assertThrows` 的区别：一个验证值，一个验证异常
- 能读懂 Java 方法签名了（返回类型 + 参数类型 + 参数名）

## 4. 暴露的问题

- 一开始把"验证抛异常"理解成"比较数值大小"，没抓住题目核心
- 写测试时自己给变量赋值再断言，没有调用被测代码 —— 测试无效
- 套模板不看场景（方法名、异常名没有按新场景改）
- Java 语法细节：缺分号、用全角括号
