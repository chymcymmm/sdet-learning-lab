# SDET Learning Lab

> 用一条真实的线，把测试能力、技术能力和 AI 能力持续串起来。

## 01｜项目定位

这是我的 **SDET 实践实验室**。

| 项 | 内容 |
|---|---|
| 主线 | **Python 接口自动化 + SQL 数据验证 + AI 提效** |
| 被测对象 | Ruffwear 真实接口（Java 后端，用 HTTP 黑盒测，与语言无关） |
| 目标 | 2027 年 3 月，北京，自动化测试 / 测试开发，**11–13K** |

## 02｜三条铁律

1. **动手 > 规划** —— 没产出、没提交，就不算学
2. **一条线 > 一堆点** —— 所有知识挂在同一个产物上
3. **每天可验证 > 每周大目标** —— 小步、连续、可交付

## 03｜那条"线"

所有知识挂在同一个产物上：**一个测 Ruffwear 真实接口的 Python 自动化项目**，逐天长大。

```text
第 1 周：一个发请求的脚本
第 3 周：能断言的接口测试
第 5 周：pytest 组织 + 参数化
第 7 周：加 SQL 双断言
第 9 周：封装成小框架
第 11 周：Jenkins 自动跑
```

学的每个东西，**当天就塞进它**。知识不再是散点，而是这条线上的一块砖。

## 05｜关键结论

- 市场主流是 **Python 接口自动化**，不是 Java 单元测试
- 1–3 年岗位要的是"**基于现有框架写用例**"，不是"造框架"
- **AI 测试岗 = 测试能力 + AI 能力**，不是纯 AI
- Java 只保留"能读、能简单调试"，不作为主线
